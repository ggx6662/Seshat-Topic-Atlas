# 题谱 · 换一台电脑怎么用

> 这份文档回答两个问题：**（1）仓库里有没有泄漏我这台机器上的私人信息？（2）换一台电脑、换个路径，能不能直接用？**
> 最后核对日期：2026-11-20。

---

## 一、一句话结论

**私人信息这一块是干净的**——没有姓名、学校、导师、邮箱、密钥，也没有本机的用户目录。
**但「配好路径就直接能跑」原本不成立**：有三处把本机绝对路径写死在数据与代码里，换机器会**静默失效**（不报错，只是功能消失）。这三处本轮已经改成可迁移的写法，后面逐条说明。

## 三、原本的三处硬阻塞（会造成「看起来正常、其实少了一半内容」）

### 阻塞 1：文献索引拿绝对路径当键 —— 已修复

`paper_meta.json` 与 `pdf_text_index.json` 原来是这样存键的：

```
G:\相关内容\AuthorKit27\知识库\新论文\2026-10-24\xxx.pdf
```

换一台电脑（或者知识库换个盘），**文件列表照常出现、分类也照常**，但标题、摘要、作者、全文检索会**全部对不上**——因为一个键都匹配不上，而且不报错。

**改法**：新增 `kb_paths.py`，把键统一成与盘符无关的形式：

```
{kb}/新论文/2026-10-24/xxx.pdf
```

- `meta_index.get()` / `fulltext.search()` 现在**两种写法都认**：传绝对路径、传 `{kb}/` 键，或者传大小写不同的路径，都能命中；
- 老的绝对路径键在查询时自动换算，所以**不重建也能用**；
- 想彻底干净，跑一次 `python tools_rebase_index.py --apply`（本仓库已经跑过，688 条键已改写，原文件备份为 `*.pre-rebase`）。

**验证过的**：把 `config.json` 的 `kb_path` 临时改成 `D:\另一个人电脑\我的知识库`，`meta_index.get()` 与 `fulltext.search()` 依然全部命中，分类推断也正常。

### 阻塞 2：arXiv 向量索引写死在 `G:\kb-vector` —— 已改成可配置

索引约 **1.47 GB**（53.8 万篇 cs 论文），不在 git 里、也不跟程序走。原来路径写死在 6 个文件里。

**改法**：`kb_vector.py` 新增 `_base_dir()`，按顺序取：

1. 环境变量 `KB_VECTOR_DIR`（最省事，换机器直接设这个）；
2. `config.json` 的 `kb_vector_path`；
3. 原来的 `G:\kb-vector`（老机器不用搬家）。

`build_bodies_cache.py`、`fetch_bge.py`、`fix_bge_meta.py`、`tools_eval_bge.py`、`oai_fetch.py` 也改成从 `kb_vector` 取目录，不再各写各的。

**仍然要做的**：人得**把索引目录拷过去**。没有索引时不会崩，但会退化——

| 功能 | 没有索引时 |
| --- | --- |
| 文献库「arXiv 全库检索」 | 红字提示「索引不完整，缺 …（先跑 --build）」 |
| 新颖性核查 | 查不了，逐条报错 |
| 文献空白页「全库核实」 | **静默消失**（宁可不说也不瞎说），所以本轮补了 `research_gap.index_status()`，能一句话说明「索引不在本机，找的是哪个目录、怎么指过去」 |

### 阻塞 3：代码里散落的默认路径 —— 已改成相对程序目录

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `kb_widget.py` `kb_root()` | 默认 `G:\相关内容\AuthorKit27\知识库` | 程序目录下的 `知识库/` |
| `kb_widget.py` 另一处 | 同上 | 同上 |
| `dashboard.py` `kb_root()` | 同上 | 同上 |
| `kbscan.py` `load_config()` | 同上 | 同上 |
| `competition/scripts/build_combined_advisor_source.mjs` | `G:/skill/knowledge-monitor/.cache_advisors.json` | 相对仓库根 |
| `competition/scripts/enrich_cached_institutions.mjs` | 同上 | 同上 |

意味着：**把整个程序文件夹拷到 U 盘，知识库放在它旁边的 `知识库/` 里，不写任何配置就能用。**

## 四、换电脑的实际步骤

1. **拷程序**：把整个 `knowledge-monitor` 文件夹拷过去（约 450 MB，若不含 `.tmp/` 与 `dist/` 更小）。
2. **装 Python**：3.10+，`numpy` / `scikit-learn` 必须；想用全文检索再加 `pymupdf`。
3. **放知识库**：把 PDF 放到程序目录下的 `知识库/`，或者改 `config.json` 的 `kb_path` 指到别处。两种都行。
4. **放索引（可选，但强烈建议）**：把 `G:\kb-vector` 整个目录拷过去，然后二选一：
   - 直接放在新机器的 `G:\kb-vector`（一行配置都不用改），或
   - 放任意位置，设环境变量 `KB_VECTOR_DIR=新路径`，或
   - 在 `config.json` 里写 `"kb_vector_path": "新路径"`。
5. **启动**：`python app_main.py`（或双击 `启动.pyw`）。没有 Python 注册到 PATH 时，`start_widget.bat` 会提示设 `KB_PYTHON`，不是写死的。

## 五、还要提醒的几件事

- **仓库现在不完整可跑**：`competition/`（整个参赛站）和 `ui_kit.py` **都还没进 git**，而代码里 `import ui_kit` 到处都是——只 clone 仓库是跑不起来的，必须整目录拷贝。
- **`.gitignore` 本轮补了 9 条**：`.tmp/`、`__pycache__/`、`backup/`、`competition/scripts/.cache/`、`*.pre-sync`、`*.pre-rebase`、`.venv/`、`assistant_memory.json`。已确认没有误伤任何已跟踪文件（`assistant_memory.json` 是唯一的例外，是有意要把它踢出仓库的）。
- **浏览器路径**：`check_site.mjs` / `capture_screenshots.mjs` / `tools_check_mobile.py` 里 Chrome 默认路径是 `C:/Program Files/Google/Chrome/Application/chrome.exe`——那是**开发回归脚本**，不是产品运行依赖；换机器时设 `CHROME_PATH` 即可。
- **一次性调研脚本**：`analyze_env_backup.py` 里还有 `F:\env-backup`、`D:\Anaconda3\envs`，那是当时查环境用的，不参与运行，可删。
