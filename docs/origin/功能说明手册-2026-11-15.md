## 0. 三分钟了解它是什么

### 0.1 一句话

**一个完全跑在你自己电脑上的科研选题工作台**：把「本地文献库 + 公开学者索引 + 实时论文源」串成一条
「定方向 → 找空白 → 出候选 → 体检 → 查导师 → 查期刊」的流水线。

### 0.2 它解决的真实痛点

| 痛点 | 它给的答案 | 在哪个页面 |
| --- | --- | --- |
| 不知道我这个方向还有什么可做 | 方法 × 任务 × 问题的组合矩阵，标出全库没人做的格子 | 文献空白 |
| 有想法但说不清楚 | 9 项结构清单逐项核查，缺什么直接给动作 | 选题工坊 |
| 不知道最近同行发了什么 | arXiv / OpenAlex / Europe PMC 三源合并，按月份排时间线 | 最新研究 |
| 找不到做这个方向的老师 | 18,281 位研究者索引，按方向匹配、按省筛选 | 导师与院校 |
| 投哪 | 按方向匹配会议期刊 + 官方主页直达 | 期刊会议 |
| 本地 300 多篇 PDF 找不到想找的 | 中文输入做语义检索，带匹配度理由 | 文献库 |

### 0.3 一句话说清「它不是什么」

- **不是文献综述生成器**。它不会替你写综述，只给你素材和结构。
- **不是选题打分器**。v4.0 起**取消了 0–100 分**，因为实测打分可以被词堆骗过（见 [3.3](#33-为什么没有分数)）。
- **不联网也能用**。除「最新研究」「抓取新论文」「下载到知识库」「导师库刷新」外，全部功能离线可用。

## 1. 启动与三种形态

### 1.1 形态对照表

| 形态 | 怎么开 | 功能范围 | 适合谁 |
| --- | --- | --- | --- |
| **桌面客户端** | `D:\miniconda3\python.exe app_main.py`，或打包版 `dist\知识库助手\知识库助手.exe` | **全功能** | 你自己 |
| **网页体验端** | 设置页点「启动网页版」，浏览器开 `http://127.0.0.1:8765` | **只读**，5 个视图 | 给同学/老师试 |
| **手机** | 同一个网页地址，同 Wi-Fi 下扫设置页二维码 | 同上，响应式布局 | 床上/课上翻 |
| **旧版桌面卡片** | `kb_widget.py`，或客户端左下角「旧版桌面卡片」 | 盯梢新论文的老界面 | 想看新论文时 |

### 1.2 网页体验端：哪些开放、哪些拒绝

**开放（5 个只读视图）**

| 接口 | 视图名 | 说明 |
| --- | --- | --- |
| `/api/overview` | 总览 | 文献数、方向数、学者数等统计 |
| `/api/topics` | 选题候选 | 输入方向生成候选 |
| `/api/gap` | 文献空白 | 方法×任务×问题矩阵 |
| `/api/advisors` | 导师与院校 | 按方向匹配 |
| `/api/taxonomy` | 方向图谱 | 24 大类 / 387 领域 |
| `/api/skills` | 科研方法论 | 7 个方法的说明 |

**明确拒绝（返回 403 + 一句人话原因）**

| 接口 | 拒绝理由（后端原文） |
| --- | --- |
| `/api/download` | 下载到知识库会写你的磁盘，体验端不开放。请在桌面客户端里做。 |
| `/api/llm` | 大模型密钥属于本机配置，体验端不开放。 |
| `/api/profile` | 个人画像含学校/导师/目标，体验端不开放。 |
| `/api/library` | 文献库全文检索会暴露本地文件路径，体验端不开放。 |
| `/api/latest` | 抓取最新论文要走外部请求，体验端限流不开放。 |

> **限制做在后端，不是前端藏起来。** 即使用 `/api/download` 直接发请求，也会被拒。

### 1.3 手机端怎么用

1. 电脑上进「设置与数据」→ 点「启动网页版」；
2. 点「显示二维码」，手机连同一个 Wi-Fi 用相机扫；
3. 首次打开后可「添加到主屏幕」，以后像 App 一样点开。

> **如实说明**：局域网是 `http`，浏览器**不会**注册 Service Worker，所以「离线可用」在手机上**不生效**。
> 只有用 localhost 或 HTTPS 打开时才完整支持 PWA。界面里也这么写。

## 2. 十二个页面逐个说明

> 每个页面按「**做什么 → 怎么用 → 输出什么 → 做不到什么**」四段写。

### 2.1 总览

**做什么**：打开就知道「现在该做什么」。

**界面上有什么**

- 顶部四格指标：文献数 / 本周新增 / 我的选题 / arXiv 跟踪（去重记录数）
- 入库节奏：一行文字（近 12 个月共几篇、本月几篇、最密的月份、几个月没入库）
- 标题高频词：一行文字（Top6 词及次数）

> 2026-11-15 起，原来的柱状图/时间轴全部改成文字。原因：这些数字一共只有十来个，
> 画成图要占掉半屏，还要读坐标轴；写成句子反而能直接读出一句结论。
- 右栏「常用入口」四宫格

**做不到什么**：不会主动提醒你「这个方向已经三个月没人发了」之类的结论，只给数字。

### 2.2 选题工坊 ★核心页

**做什么**：从一句方向名到一批可比较的候选选题。

**怎么用**

1. 在输入框写方向，如「红外小目标检测」「Mamba 多模态融合」；
2. 点「生成候选」（或回车）；
3. 左边列表出现 **18 个候选**，右边是选中候选的详情。

**每个候选带什么**

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| 标题 | 「方向 × 切入角度」组合出的候选 | 「红外小目标检测 × 开放词汇」 |
| 分类 | 三类之一 | 稳健邻接 / 跨领域迁移 / 高风险高回报 |
| **为什么值得做** | 每个候选**独立**的理由，不是模板套话 | 见下 |
| **最小验证** | 两周内能做完、能判断继续或停止的最小实验 | 见下 |
| **验证问题** | 这个候选必须回答的具体问题 | 见下 |

**角度库共 22 个**

| 类别 | 数量 | 角度 |
| --- | --- | --- |
| 稳健邻接 | 9 | 跨域泛化 / 开放词汇 / 轻量化 / 小样本 / 自监督 / 可解释 / 评测 / 鲁棒性 / 多尺度 |
| 跨领域迁移 | 8 | 分割 / 跟踪 / 视频 / 多模态 / 三维 / 扩散 / 语言 / 事件相机 |
| 高风险高回报 | 5 | 问题重构 / 失效机理 / 新任务 / 理论解释 / 大规模复现 |

**实测结论**：18 个候选 → **18 种理由、18 个验证问题**（旧版是 18 个候选配 1 套模板套话）。

**右侧动作按钮**

| 按钮 | 作用 |
| --- | --- |
| 方法论帮助 | 弹窗列出 7 个科研方法，告诉你下一步该用哪个 |
| 存为创新点 | 写进创新点库，带阶段和结构诊断结果 |
| **AI 挑刺** | 让配好的大模型以审稿人视角挑毛病（需先接大模型） |
| 生成交接提示词 | 把候选 + 诊断 + 导师 + venue 打包成一段可粘贴的提示词 |
| 复制清单 | 复制全部候选 |
| 用方法论改进这个选题 | 跳到科研方法论页，带上当前选题 |

**做不到什么**

- 候选是**组合生成**的，不是从文献里挖出来的。它保证「结构完整、角度合理」，**不保证创新**。
- 方向名太长或太生僻时，分类识别置信度会低，界面会显示出来。

**新颖性核查（生成后自动跑，约 25 秒）**

候选的分数只说明「这条题结构完整、角度新」，**不回答「世界上有没有人做过」**。所以候选一出现，后台会把**前 8 条**拿去 arXiv 全库 53.8 万篇查重。

| 档位 | 判据 | 界面表现 |
| --- | --- | --- |
| 撞车风险高 | 最像的论文 ≥ 0.80，或 0.70 以上且近两年有 3 篇以上 | 候选卡红徽章「撞车风险高」 |
| 邻域较挤 | 最像的 ≥ 0.62，或近两年 6 篇以上 | 黄徽章「邻域较挤」 |
| 没查到近邻 | 以上都不满足 | 不显示徽章 |

点开候选，详情面板「新颖性核查」会列出**最像的 3 篇真实论文**（分数 / 年月 / 可点开 arXiv），最后固定一行：

> 核查范围：arXiv cs 近三年 53.8 万篇。没查到不等于没人做过 —— 会议正刊、期刊、工业界的工作不在里面。

**只核前 8 条**是有意为之：一条约 3 秒，18 条全核要一分钟，用户等不起。第 9 条起显示「这条没有核查（只核前 8 条，排序靠后的没排上）」。

**判档口径为什么改了三次**（这段值得看，它说明「看起来更严格」不等于「更对」）：

1. 最初让关键词层单独判「撞车」→ 红外和医学**全部**被判撞车。因为 `detection` × 任何角度都有 500–1300 篇，那是通用词拥挤，不是真撞车。
2. 改成看「该角度占本方向的比重」→ 红外 2%、医学 4%，两者占比差不离，但语义相似度差一大截（0.54 vs 0.82）。**占比分不出「顺口提一句」和「真在做」**。
3. 最终：**语义近邻定档，关键词层只在语义不够近时抬到「邻域较挤」**，绝不单独抬到「撞车」。

### 2.3 文献空白 ★核心页

**做什么**：看「哪些方法×任务的组合，我这个库里还没人做过」。

**界面结构**

| 区域 | 内容 |
| --- | --- |
| 左栏顶部 | 方法 × 任务密度，**一行一个方法**：「对比学习（共 N 篇）→ 检测 12 · 分割 8 …」 |
| 左栏 | 「已经做得很密」的组合列表（带篇数） |
| 右栏顶部 | **问题维度空白**（如「医学场景下小目标」没人做） |
| 右栏 | 方法与任务的空白组合 |

**怎么用**

1. 输入关键词（默认「*」= 全库）；
2. 每格可点击「存为创新点」。

**实测数据（本地库 343 篇 + 全库核实）**

本地库的说法和全库核实常常**不一致**，而且不一致本身就是信息：

| 组合 | 本地篇数 | 全库篇数 | 全库结论 |
| --- | --- | --- | --- |
| YOLO × 检测 | 51 | — | 本地已经很挤 |
| 对比学习 × 检测 | **0** | **603** | **拥挤**，别再当创新点 |
| 对比学习 × 融合 | **0** | **868** | **拥挤** |
| SAM/分割基础模型 × 跟踪 | **0** | 83 | 稀疏 |

前三行就是为什么必须做全库核实：**本地 0 篇看着像真空白，全库其实有六百多篇**。
早期版本正是把这种「查询写错了」误报成「真空白」的（中文「检测」没翻译成 `object detection`，AND 里挂了个中文词，必然命中 0）。

**做不到什么**

- 本地库只是「你收藏了什么」，不等于学界现状。
- **已缓解**：右栏每条空白都会自动拿去 **arXiv 全库 53.8 万篇**核实一遍，并给出「全库 52 篇 · 稀疏」这样的色块（见下）。
- **仍未做到**：全库核实只覆盖 arXiv cs 近三年。会议正刊、期刊、工业界内部工作不在里面 —— 「没查到」只能读作「在我们能看到的范围内没查到」。

**全库核实（自动，约 20–40 秒）**

打开页面时先立刻显示本地结论（0.1 秒），后台同时把每条空白拿去全库核实。
核实完，每条空白右侧多一个色块，下方多一行结论：

| 色块 | 全库篇数 | 意思 |
| --- | --- | --- |
| 绿「全库 12 篇」 | < 20 | **真空白**，值得认真看 |
| 黄「全库 52 篇」 | 20–200 | **稀疏**，有人做过，要讲清差异化 |
| 红「全库 603 篇」 | > 200 | **拥挤**，别当创新点 |

问题维度空白还多一行「该场景在全库 4,451 篇文献里是活跃赛道 —— 空白是场景内的细分缺口，不是场景本身没人做」。
这一行很重要：它区分了「医学本身没人做」和「医学里的小目标没人做」。

**你做不做得动（读了「个人画像 → 我的硬条件」才显示）**

每条空白下方会自动判断它和你填的算力/周期/风格冲不冲突：

- 红字「按你填的条件：这条做不完 —— 要「单卡24G」档算力，你填的是「无算力」」
- 黄字「按你填的条件：要挑做法 —— 要「单卡消费级」档算力，你填的是「无算力」」
- 黄字「按你填的条件：做全套吃力，可以先做最小验证」

最后这条是**降级规则**：若这条空白本身是全库「稀疏/真空白」，即使角度要求的档位更高，也只提示「做全套吃力」而不是「做不完」。
理由是一片基本没人的地里，起步只需要一个最小验证就能判断值不值得继续 —— 把这类机会一律判死，等于替用户放弃。

没填硬条件时这一行不出现，不占版面。

### 2.4 最新研究 ★核心页

**做什么**：按方向抓**最近发表**的论文，三源合并。

**数据源**

| 源 | 覆盖 | 状态 |
| --- | --- | --- |
| arXiv | 预印本，CS 最全 | ✅ 可用 |
| OpenAlex | 期刊 + 会议正式发表 | ✅ 可用 |
| Europe PMC | 生物医学为主，也收部分 CS 交叉 | ✅ 可用 |
| Semantic Scholar | — | ❌ 无 key 直接 429 |
| DBLP | — | ❌ 服务端 500 |
| CORE | — | ❌ 429 |
| Crossref | 正式出版 | ❌ **已移除**（原因见下） |

> **为什么删了 Crossref**：它的 `sort=published` 按错误元数据排序，返回 2106 年、2031 年的掠夺性期刊论文
> （GSC Advanced Research、Basrah Journal of Veterinary Research），对「找最新」毫无用处。

**怎么用**

1. 输入方向，或点快捷词（红外小目标检测 / 图像融合 / Mamba / 扩散模型 / 多模态大模型）；
2. 勾数据源（默认三个全选）；
3. 选时间范围（最近 1 / 3 / 6 个月、1 年）；
4. 点「抓取」。

**结果怎么显示**

- 按**月份分组**的时间线；
- 每篇一张卡：标题（点开原文）、日期、来源徽章、DOI；
- 跨源重复的论文会合并，标「OpenAlex +arXiv」。

**每篇能做什么**

| 按钮 | 作用 |
| --- | --- |
| 打开原文 | 浏览器打开 |
| 复制标题 | 复制到剪贴板 |
| 存为已有工作 | 写进创新点库，标题前缀 `【已有工作】`，`kind="external"` |
| **下载到知识库** | 走 `kb_download.download()` 存进本地库（见 [2.10](#210-文献库)） |
| 下载前 5 篇 | 批量下载最上面 5 篇 |

**AI 增强（需接大模型）**

| 功能 | 触发条件 | 说明 |
| --- | --- | --- |
| **检索式改写** | 本地词表匹配到 **0 篇** 时才触发 | 大模型把中文方向改成 arXiv 检索式，校验前缀和后解析后重抓 |
| **AI 总结这批论文** | 手动点 | 输出「3 个技术走向 + 1 条未解决问题」，标注「由大模型生成 · 引用前请核对原文」 |

**实测数据（2026-11-13）**

| 方向 | arxiv | openalex | europepmc | 去重后 | 最新 |
| --- | --- | --- | --- | --- | --- |
| 红外小目标检测 | 25 | 23 | 24 | **64 篇** | 2026-11-11 |

**做不到什么**

- 各源检索语法不同，`override_query` 模式下**只查 arXiv**。
- Europe PMC 偏生物医学，纯 CS 方向命中较少。
- 最新论文引用数都是 0，所以**按日期排、不按引用排**。

### 2.10 文献库

**做什么**：本地 PDF 台账 + 检索。

**当前规模**：343 篇 PDF，全文索引覆盖 100%。

**三种检索**

| 模式 | 怎么触发 | 认中文吗 | 速度 | 原理 |
| --- | --- | --- | --- | --- |

**为什么只记零结果的检索**：正常的浏览一天能点几十次，如果都记，
500 条上限两周就满了，而「搜不到」才是真正值得记住的缺口。

#### 提示词现在吃什么

`prompt_context.py` 把画像拼成一段「使用者情况」：

- 身份（学位阶段 / 学校 / 目标）与算力、周期、风格、禁忌；
- 近期关注方向 Top3、常用角度 Top3、常用策略 Top3（低于门槛的「看过一次」不算）；
- 紧急度 / 兴趣 / 心情（只在极端时输出，平静时不占字数）；
- 最近 3 条记忆锚点（经过注意力倾斜重排）。

**铁律：没有信息就不输出这一段。** 宁可少一段，也绝不输出「暂无偏好」——
模型会照着占位文字编出不存在的理由，这一条写进了自动化测试。

生效位置三处：科研方法论的「这一步的提示词」、「完整改进计划」、选题工坊的「交接提示词」。

**核心机制：注意力倾斜（Attention Tilt），不是物理删除**

| 紧急度 | 危机类记忆权重 | 日常类记忆权重 |
| --- | --- | --- |
| 0–40 | ×1.0 | ×1.0 |
| 60 | ×2.0 | ×0.55 |
| ≥80 | ×3.0 | ×0.1 |

- **全量检索一条不删**，只做重排和压缩；
- 界面如实交代「共 N 条全部交给模型」。

**紧急度怎么自动算**：按截止日对数插值 —— ≥30 天 → 20，7 天 → 62，1 天 → 92，过期 → 100。

**画像怎么影响选题排序**：`topic_gen.apply_profile()`，偏好权重上限 `TILT_CAP = 12.0`。

**做不到什么**

- 它**不联网学习**，只根据你本机的操作累积（查导师、存选题等）。
- 导出的脱敏画像去掉了学校/导师。
- 只在本机、只在你自己的操作里学；换一台机器就是空白画像。
- 没有「训练」这回事，也没有接大模型做推断 —— 它只是一份会被读进提示词的本地事实表。

## 3. 核心引擎（页面背后的算法）

> 这一节是给你复核「方法是不是科学」用的。每个引擎都写了它**为什么这么设计**和**它的假设在哪会不成立**。

### 3.1 方向识别

- OCR 级：方向名 → 24 大类 + 387 领域；
- 短英文缩写**必须词边界匹配**（`ics`、`ar`、`network` 用子串匹配会灾难性误判，踩过）；
- 查不到时走**近邻扩展**，标注「相邻方向：立体视觉与SLAM」。

**实测**：「单目深度估计」→ 识别为 计算机视觉 / 单目与双目深度估计，置信度 92%。
近邻扩展能查到 Marc Pollefeys(ETH)、Jia Deng(Princeton)、Jiwen Lu(清华)。

### 3.2 选题候选生成（topic_gen）

```
候选 = 方向 × 切入角度
```

每个候选独立生成 `reason` / `min_experiment` / `questions`，**不复用模板**。

### 3.3 为什么没有分数

| 输入 | 旧版得分 | 结论 |
| --- | --- | --- |
| 真问题、朴素描述 | 30 分 | 被判「重做问题定义」 |
| **毫无内容的词堆** | **77 分** | **被判「投稿候选」** |

把「消融、baseline、指标、单卡 GPU、停止条件」堆在一起就能骗过评分系统。
**现在的做法：不评分，只核查结构，并且不允许裸词糊弄** —— 「指标」两个字不算定义了指标，必须出现 AP50 / F1 / p95 时延。

### 3.4 结构诊断（research_diagnose）

9 项硬条件：`problem / mechanism / baseline / data / metric / ablation / budget / stop / scope`。

### 3.5 文献空白（research_gap）

- 中文关键词先映射成英文（论文标题是英文，直接用「红外」匹配会得 0 篇）；
- `_IMPLAUSIBLE` 过滤掉物理上不可能的组合；
- `ISSUE_APPLIES` 判断某个问题维度对某类任务是否适用。

### 3.6 多源检索（paper_sources）

三个源都有各自的坑，代码里逐个处理了：

| 源 | 坑 | 处理 |
| --- | --- | --- |
| OpenAlex | 用 `search=` 会走慢通道并 429 | 改用 `filter=from_publication_date:...,title_and_abstract.search:...` |
| OpenAlex | 搜索串不写 AND 会当 OR 处理，返回 1781 篇散装结果（含「硅纳米颗粒热行为」） | 显式写 AND → 225 篇精确结果 |
| Europe PMC | 默认 OR 且搜全文，裸 AND 给 26473 条（首条是「木寡糖对甲烷合成」） | 改 `TITLE_ABS:x AND TITLE_ABS:"y"` → 272 条 |
| 全部 | 撤稿/勘误/编者按混进结果 | `_NOISE_TITLE` + `_BAD_TYPES` 过滤，残留噪音 0 |

### 3.7 语义检索（semantic_search）

TF-IDF → TruncatedSVD(180) → L2 归一化；索引 4.4 MB。

**全库索引的存储格式（2026-11-14 重做，内存 -70%）**

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `meta.bin` | **75 MB** | ids / titles / dates / cats，定长+堆打包 |
| `emb.npy` | 185 MB | float16 (538189, 180)，**按 mmap 打开，不进堆** |
| `svd.pkl` | 137 MB | TruncatedSVD 的 180×200000 投影矩阵 |
| `tfidf.pkl` | 7 MB | 词表 |

之前三处搜索都写 `E = d["emb"].astype(np.float32)`，每次搜索把 185 MB 整块转成 387 MB 用完即弃 —— 矩阵乘本身会自动提升类型，这次改成了直接乘。

> 为什么改：旧格式 `np.savez(meta.npz)` 有两个毛病 —— ① `savez` **不压缩**，835 MB 落盘就是 835 MB 进内存；② `np.array(list_of_str)` 推出的是**定长 `<U250`**，538189 × 250 × 4 字节 = 513 MB，而标题平均只有 80 个字符，**约 700 MB 是零填充**。
> 换成「定长数组 + 拼接大 bytes + 偏移表」后 titles 513→46 MB、cats 269→10.5 MB。

**实测收益**

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 索引加载 | 10.4 秒 | **0.21 秒** |
| 加载后常驻内存 | 1342 MB | **397 MB** |
| meta 文件 | 835 MB | **75 MB** |
| 检索结果 | — | 完全一致（「红外+小目标」同为 183 篇） |

**兼容**：旧的 `meta.npz` 仍能读（`load()` 里 `meta_format == "npz-legacy"` 分支），下次 `--build` 才写 `meta.bin`。所以别人机器上不重建也不会坏。

**启动预热已关闭**：旧逻辑会在启动 4 秒后跑一遍用户最常用的查询，把 1.2 GB 索引顶进内存。现在加载只要 0.2 秒，预热变成纯粹的负担，`app_main._warm_search()` 改成了直接 `return`（旧代码留在下面作参考）。

**同一套向量还服务另外三处**：

| 用处 | 入口 | 数据规模 |
| --- | --- | --- |
| 本地库语义检索 | `page_library.vector_search()` | 本地 343 篇 |
| arXiv 全库语义检索 | `page_library.vector_search()` | 53.8 万篇，180 维 |
| 多词交集检索（AND） | `kb_vector.search_and()` | 同上 |
| 新颖性核查 | `novelty_check.check()` | 同上 |

**多词交集检索**是向量检索的补丁，不是替代品：向量擅长「意思接近」，但 180 维 SVD 会把低频词压掉。
实测「图像去雾」纯向量 Top5 **0/5** 命中 —— 全被压成「通用图像恢复」。
所以加了 AND 检索：`去雾 图像 -restoration` → 152 篇，Top10 **9/10** 命中。
排序用「向量相关度 × 词密度」相乘：纯向量会排出通用检测论文，纯密度会偏爱关键词堆砌的长摘要，相乘互相制衡。

**改过的两个参数不要动**（都是实测换来的）：

- `lightweight` 同义词组里**不能**放 `efficient / real-time / mobile / flops`。放了之后「轻量化+检测」交集从 2,981 暴涨到 16,667 篇，Top10 命中从 7/10 掉到 1/10 —— 这几个词每篇检测论文都有。
- 排除词 `-x` **不套同义词组**，只展开单复数。同义组是为了扩大召回，排除词一扩就把整个领域误杀。

### 3.8 新颖性核查（novelty_check）

两层判据，各管一件事：

| 层 | 方法 | 回答 |
| --- | --- | --- |
| 近邻层 | `kb_vector.search(phrase, k=5)` | 最像的有多像？ |
| 词层 | `kb_vector.count_and(...)` | 两三个概念被原样写在一起的篇数 |

**查询是怎么拼的**：`候选标题 + 角度英文词 + 方向的英文展开`。
踩过的坑：单方向候选**没有** `combo`（那是跨领域组合才有的），第一版直接从 combo 取词 → A 为空 → 查询退化成只剩 `domain generalization` → 查出一堆数学拓扑论文（`Separating domains from algebraic domains` 0.797）还给了高分。现在 `a = combo["a"] or direction`，direction 必有兜底。

**性能**：`count_and` 走预筛池（先按方向取最像的 60,000 篇再 AND 计数），单条 0.38–1.45 秒。
坑：预筛 hint 若是中文，`_seg_vec` 走英文 tf-idf 会返回 None，**静默退化成全量扫描**（每次 2.2 秒）。现在先判 `_has_cjk()` 走中文查询向量。
另一个坑：**预筛 hint 必须用方向本身，不能用整条 phrase** —— phrase 含角度词会让池偏向「讲这个角度」的论文，分母从 987 掉到 171，占比虚高。

### 3.9 学者索引（advisor_index）

- 合并键优先级：ORCID > (姓名, 引用, 论文数) > (姓名, 机构)；
- 院校名**先去重再归一**会把同一学者当两人，必须**先归一再去重**；
- 中文姓名归一（修好 45 个「茜 王」这类倒序）；
- 排序：`(-(score//5), -impact, name)`，`impact = log1p(cited)*2.0 + log1p(works)*0.5`；
- 结果落盘缓存 `.cache_advisors.json`（13 MB），按 5 个源文件 mtime 做签名。

| 层 | 现象 | 根因 | 修法 |

| 字体 | 侧栏文字笔画发灰、边缘毛糙 | `FONT_STACK` 首位是 **DengXian（等线）**，但这台机器**根本没装**，Tk 对不存在的字体族**静默回退**，字号按等线的度量算、字形来自别的字体 | 新增 `pick_fonts(root)`：启动时用 `tkfont.families()` 探测，按 `Microsoft YaHei UI → 微软雅黑 → Noto Sans SC → 思源黑体 → 苹方 → 等线 → 黑体` 顺序挑第一个真实存在的 |
| 缩放 | 字号偏小 | `_apply_font_scale()` 只在 `main()` 里、`App()` **之后**调用，已建控件全是默认值；`_SCALE` 一直是 1.0 | 移到 `App.__init__` 里、建控件之前 |
| 卡框 | 卡片四周一圈约 10px 的**厚灰带** | `Card._sync` 调 `_round_rect()` 画了「外圈实心多边形（fill=描边色）+ 内圈白色多边形」。外圈每边比内圈多 1 个**逻辑**像素，125% 缩放下放大成 2–3 个设备像素，再被 `smooth=True` 抗锯齿扩散成一条带 | `card_outline()` 在浅色下一律 `return None`，层级全交给底色（画布 `#eff0f3` vs 卡片 `#ffffff`） |

**第 13 版最值得记的一条教训**：改了两轮都没生效，因为 `card_outline()` 里原本写着 `return border or None`，想保留「显式传 `border` 的调用方仍画框」——**但 `Card.__init__` 的默认值本身就是 `border=LINE`**，等于所有卡片都走进了这条分支。判断「某个开关是否生效」不能只看函数返回值，要直接读绘制图元的坐标：探针打印出 `内圈 bbox=(1,1)-(326,134)` / `外圈 bbox=(-1,-1)-(328,136)` 才定位到真相。

**同版本修掉的截图工具 bug**：`tools_shot_pages_all.py` 先截深色、再 `apply_theme("light")` 截浅色，而 `apply_theme` 会**写盘**。于是下一次运行时 `App()` 读到的就是 `light`，所谓「深色截图」其实拍的是浅色——两张图字节完全相同。现在脚本先记住原主题，深色/浅色都显式开关，结束时原样写回。

16px 只画 2 条线：画布只有 16 个像素，要塞下圆角、3 条线和 2 个间距，线距会只剩 2px，缩到任务栏仍是一团。

**显示时的真实 bug（值得记）**：`tk.PhotoImage(file=...)` **不做任何重采样**——图多少像素就贴多少像素。125% 缩放下侧栏要 32 逻辑像素 = 40 物理像素，直接塞 32px 的图，Tk 按 32px 原样摆上去，图形只占视觉方框的 80%，看着比旁边文字小一号；塞 128px 又被裁。现在统一走 `app_theme.load_bitmap(path, logical_px)`：按设备像素 `logical_px × dpi_scale()` 用 LANCZOS 预缩后再交给 Tk。

**`dpi_scale()` 不能读 Tk 的 `winfo_fpixels("1i")`**：本进程没声明 DPI 感知，Tk 报的是逻辑 DPI（实测 95.976，即 1.0），而系统实际缩放是 125%（注册表 `AppliedDPI = 120`）。一开始就是这么写错的，图仍然只有 32px。现在与 `app_main._detect_scale()` 同源：注册表 → `GetDpiForSystem` → 1.0。

**`fill_wrap()` 余量不足（影响全项目）**：Tk 排版时 Label 会把自己的左右 `padx` 打进去再折行，可用宽度是「容器宽 − 2×padx」，而父容器的 `<Configure>` 给的是外宽。原来按「容器宽 − pad」算，期刊会议右栏（容器 396、Label 各 padx=6）就出现过一个「准」字被挤到第二行。现在统一取 `pad + 8` 作为安全余量。

**这一版另修的三处**：期刊会议右栏去掉「用浏览器打开」按钮（网址本身可点，按钮把域名挤成两行）；截稿提醒改成跟随宽度换行；研究计划**空计划时隐藏「加阶段」**（空态卡里已有「用推荐阶段起步」，两个按钮并排会让人以为必须先建阶段）；文献空白的警告条从硬编码深黄底改成 `T.tint(T.WARN, …)`（浅色主题下原来是一块脏黄）。

**⑧ 2026-11-16 性能：长列表改成按滚动现建（`ui_parts.LazyList`）**

用户的原话是「加载依旧是那么的不流畅」。实测各页切页耗时（同一窗口、首次访问）：

| 页面 | 改前 | 改后 | 根因 |
| --- | --- | --- | --- |
| 期刊会议 | 1.48s | 0.31s | 126 行 × 6 个 Label = 1834 个控件一次性建完 |
| 文献库 | 0.94s | 0.11s | 345 行，切走再切回还要重建一遍 |
| 选题工坊 | 3.20s | 0.07s | 首次会卡在 `advisor_index` 冷启动，现在改由后台线程预热 |
| 方向图谱 | 0.53s | 0.07s | 同上 |
| 导师与院校 | 0.76s | 0.17s | 同上 |

做法：行仍然只写一遍构造函数，但建完之后立刻 `pack_forget()`（Tk 不给 forget 的控件算几何），只按滚动位置把可见的 ±4 行 pack 出来；滚到第 300 行也只同时存在 20 多个控件。

- **滚动比例必须自己算**：滚动条命令交给 `LazyList`，`moveto` 按「行号 × 行高 ÷ 虚拟总高」换算。撑高条的高度也按同一个公式给，两处不同源滚动条会和列表错位。
- 容器**一开始就要占一屏高**：否则第一次 `fill()` 读到 `winfo_height() == 1`，只建 4 行，首屏一片空白（这个 bug 出现过，截图里是空白的）。
- 滚一下把剩下的行全建出来，也是同一个原因（`_need()` 里 `hi` 被算成了 `count`）。
- 被 `ScrollArea.clear()` 销毁后，延迟的 `fill()` 会撞上 `bad window path name`，所以每次 fill 前先 `winfo_exists()`。

**文献库另加一条快路径**：进页面时先用内存里的元数据（`meta_index`）把列表铺出来，再去后台线程补「分类计数 / 入库节奏 / 语义索引」。快路径不查语义索引，所以那一趟**不写**索引数字——否则「索引 0 篇」会被当成索引丢了。

**测试口径也跟着改了**：原来 e2e 断言「首屏 50 条 / 点加载更多 +50」，现在是「首屏建了 8–N 行、但不等于总行数」「滚到 90% 后建出的行数变多但没全建」。

**2026-11-15 第 14 版（撤掉卡片流，加研究计划）**：

用户对第 11 版的四列卡片流给了一句判决：「这块我不需要，我认为不太科学，看的不舒服」。

**复盘它为什么不科学**（这是这一版真正的收获）：

| 问题 | 具体表现 |
| --- | --- |
| 四种东西摆成同一种卡片 | 「我的选题」是用户自己写的、「最近入库」是磁盘上有什么、「导师候选」是上次查询的残留、「下一步」是系统推荐的。外观一样，但**可信度完全不同**，读的人得先在心里给每列打标签 |
| 「下一步」在替用户做决定 | 它按「有没有选题」猜下一步。猜对了没功劳，猜错了就是误导——**推荐的语气越肯定，越像指令** |
| 列与列之间没有关系 | 四列各自独立，读完一列不回滚也接不上下一列，所谓「一屏看见全貌」其实只是「一屏看见四堆东西」 |

**改法**：总览只保留一块「研究计划」摘要（当前阶段 + 剩余天数 + 三条最近待办 + 一句总结），详细的阶段与待办放进侧栏「个人 → 研究计划」独立页面。总览回答的问题没变——**「我现在该做什么」**——但答案来自**用户自己排的计划**，系统只负责把剩余时间和待办摆出来。

研究计划页有四个维度（用户确认全部要）：**阶段与截止日期**（时间轴宽度按到截止日的远近画，等比例，不画刻度也能看出哪段最长）、**待办勾选**（未完成在前，已完成的沉底淡化但不删）、**挂到某条选题或某个研究方向**（挂上去以后总览和详情都显示「选题：…」）、**每周投入时间**（这周还剩几小时）。

**四件刻意不做的事**（写进 `plan_store.py` 的 docstring，改动前请先读）：

1. **不预测工期**。系统没有任何数据能推出「你的实验要跑几周」，所以只做减法（截止日 − 今天），不做估算。
2. **不自动往计划里塞任务**。计划的内容是用户的判断，系统插进去的条目会让人分不清哪些是自己定的。
3. **不给完成度百分比**。「待办 3 / 4」是计数的原样呈现；折算成「完成度 75%」会暗示「四件里三件一样重」，而实际上它们并不同等。
4. **不弹窗提醒**。总览里看得见就够了；桌面通知会把人从正在做的事里拽出来。

**这一版修掉的四个布局 bug**：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 空态飘到页面下半屏，上面一大片空白 | `EmptyState` 末尾给**最后一行** `grid_rowconfigure(weight=1)`，只有 4 个控件时这一行被撑高、内容在其中垂直居中；外层 `_body` 又是 `pack(expand=True)`，自己就吃掉 409px（`reqheight=1`） | `EmptyState` 改用独立的零高度 `spacer` 行吸收剩余空间；计划页空态时整体 `pack_forget()` 两栏区，有数据时按原位置 `pack(after=metric_row)` 挂回 |
| 待办行里标题和「阶段 · 剩余天数」叠在一起 | 标题先 `pack(side="left", expand=True)`，元信息再 `pack(side="right")`——Tk 已把宽度分给标题，元信息被挤出原位 | 元信息改到**独立第二行**（缩进对齐正文），不再与标题抢宽度；正文换行用 `T.fill_wrap()` 跟随列表实际宽度 |
| 空计划时显示「当前阶段 — · 待办 0 / 0 · 已过期 0」 | 指标行无条件渲染 | 空计划时整行 `pack_forget()`，等真有计划再出现（一串零看起来像系统算错） |
| 空态按钮被撑成横贯整页的长条 | `EmptyState._add()` 一律 `sticky="new"` | 按钮用 `sticky="w"` 只占自身宽度，文字类控件才拉满 |

同一时间还剩两条硬规矩（改动界面时请守住）：**字号不小于 13px**；**颜色不单独表意**（颜色旁边必须有文字）。

**2026-11-15 界面第 8 版（继续简化 + 缩放提速）**：

用户提了两件事：「为什么放大缩小的时候不那么流畅」和「总览界面的效果为什么还是有些粗糙简陋」。

**① 缩放从 483ms/帧 降到 83ms/帧（5.8 倍）**。用脚本连续改窗口宽度并计时，定位到两个真根因：

| 根因 | 原来的做法 | 改法 |
| --- | --- | --- |
| 科研导航每帧重建全部瓦片 | `TileGrid._layout()` 在列数变化时 `destroy()` 11 个瓦片再重建（每格含图标画布 + 多个标签 + 三个鼠标绑定）。拖动时列数在 4↔3↔2 之间来回跳，**每帧付一次**（实测 318–710ms） | 新增 `reflow(cols)`：只对行列号变了的瓦片调 `grid_configure()`。同列数 **0.0–0.2ms**，真换列 176ms |
| 卡片每 16ms 结算一次高度 | `Card._sync()` 每次读 `body.winfo_reqheight()` 再 `configure(height=)`，130+ 控件随之重新布局，拖动时高度在 394/298/271 之间**跳了 29 次** | 高度拆成两把锁；拖动中间帧沿用上次定稿高度不重算；防抖从 16ms 改成 **180ms**，松手后才结算一次 |

**踩过的坑（否则改了也白改）**：拖动帧虽不再重算高度，但**缓存被提前写掉了**，松手时 `_run_settle` 以为「高度没变」直接跳过 —— 卡片永远停在拖动开始时的旧值（实测 settle 前后 `last_h 394→394` 纹丝不动）。修法是拖动帧只读不写缓存。

**② 总览页从「七行平铺」改成有主次**：数据概览原来是 7 行表格，把「知识库文献 344 / 已提取标题 340 / 语义索引 343」这些**几乎同源的数字**排成一条竖线，读者要自己判断哪个重要——所有东西一样大一样重 = 没有层级 = 粗糙。现在改成 **4 个主指标横排**（我的选题 / 知识库文献 / 导师名单 / 研究方向）+ 一行过程指标。

同时修的：科研导航瓦片去掉固定宽高（原来瓦片比格子窄、右侧留白参差）；角标改到**独立第三行**（原来标题与角标抢同一行，标题被压折行，「科研方法论 7 套」那格比旁边高半行）；说明文字跟随瓦片宽度换行；每格描一圈极淡的边（深色下用 `LINE` 而不是 `LINE_SOFT`，后者离卡片色只差一档，环几乎看不见，4×3 排开会糊成一片文字流）。

指标卡的读法也改了：**名称在上、数字在下**。原来是大数字在上、名称在下，四个数字字号一样大时视线先被数字拽走，反而不知道在看什么。

**④ 卡片底色三处真 bug**（截图里表现为「选题工坊中间那张卡没有底色，是一个比画布更暗、比卡片更大的方块」）：

| 位置 | 错在哪 | 症状 |
| --- | --- | --- |
| `Card.__init__` | Frame 与内层 Canvas 都用 `bg=parent.cget("bg")`（父容器色），而不是构造函数收到的 `bg` | 卡片拿到画布色，只有 `body` 是卡片色 |
| `ScrollArea._sync_theme()` | 判断条件是 `stale != BG`，而页面显式传 `bg=T.CARD` 时这个条件**永远成立**；该函数绑在 `<Configure>` 上 `add="+"` | 每次 Configure 都把滚动区刷成画布色，等于在卡片中间挖了个更暗的矩形 |
| `app_theme.CARD` | `RADIUS`/`_CARD_KEY` 曾把 `CARD` 映射到 `"canvas"` | 卡片与页面同色，只能靠描边区分 → 满屏「黑框」 |

第三处的修法：`CARD` 取 `surface_card`（深色 `#15181c`，比画布 `#0b0d10` 亮一档），并且**卡片一律不画描边**，层级全交给底色台阶。

**⑤ 导师页空态被顶到屏幕最底部**：`card.pack(fill="both", expand=True)` 一直占着全高，空态卡只能在它下面排 → 上空 570px、引导卡贴底。改成空态时把外层卡片 `pack_forget()`，有结果再 `pack` 回来。

**调试法（值得复用，比逐文件读代码快）**：写一个临时脚本，按**屏幕坐标**递归命中测试，把该点下所有层的 class / 几何 / `bg` 打出来 —— 这次一眼就看出是 `ScrollArea` 那层在做怪。

**③ 顺带修的标题脏数据**：最近入库的论文标题带着 arXiv 编号（`… for MODIS Spectral-Temporal 2610 36750v1`）和 `paper` 后缀（`… CVPRF 2026 paper`）。根因是下载器把 arXiv 号拼进了文件名，`build_paper_meta.py` 从文件名还原标题时没剥掉。现在 `title_from_filename()` 与 `meta_index.clean_title()` 双层清洗。**注意**：有一篇的原文件名被磁盘截断成 83 字符（`…Adversarial Patch for I`），那半截文字找不回来，只能重下。

> ⚠️ **本轮出过一次事故，已修复**：`tools_test_chat.py` 的 `finally` 里有 `elif not had: os.remove(L.CONFIG_FILE)` —— 只要测试隔离没真正生效，跑一次测试就会**把用户的真实 `llm_config.json`（API 密钥）删掉**。现在判断了「是不是真实目录」，真实目录一律不碰。教训：**任何 `os.remove` 都要先确认路径在临时目录里**。

## 5. 大模型接入

### 5.1 设计原则

1. **完全可选** —— 没配 key，全部功能照常走本地词表 / 语义检索；
2. **key 只存本机** `llm_config.json`；
3. **失败必须降级**，返回 None 不让界面卡死；
4. **模型输出一律标注「需你判断」**。

### 5.2 支持的服务商

| 服务商 | base_url | 默认模型 | 要 key 吗 |

| DeepSeek | `https://api.deepseek.com/v1` | deepseek-chat | ✅ |
| 通义千问 | dashscope compatible-mode/v1 | qwen-plus | ✅ |

| 自定义 | 任意 OpenAI 兼容 | — | 看服务 |

> 选 OpenAI 兼容协议，是因为上面这些都支持 `/chat/completions`，一套代码通吃。

### 5.3 五处用法

| 位置 | 功能 | 触发 |
| --- | --- | --- |
| 最新研究 | 检索式改写 | 本地词表 0 篇时**自动**触发 |
| 最新研究 | AI 总结这批论文 | 手动点 |
| 选题工坊 | AI 挑刺 | 手动点 |
| 创新点库 | AI 审稿意见 | 手动点 |
| **创新点库** | **和模型继续聊（多轮对话）** | 选中一条选题后手动点 |

### 5.4 对话：和模型继续聊

「AI 审稿意见」是一次性的，「和模型继续聊」是**连续多轮**的，可以追问「那第三条具体怎么改」「如果能用的卡只有一张呢」。

- **入口**：创新点库 → 选中一条 → 操作条上的「和模型继续聊」。面板出现在右侧详情区。
- **对话里会自动带上什么**：这条选题的标题、所属方向、你的原始想法（锚点段）+ 你的画像（身份 / 目标 / 时间紧迫度 / 心境 / 算力 / 期限 / 偏好 / 不碰的方向 / 最近看的方向）。
- **不会带什么**：不带你的密码与密钥；不带整库文献正文（只在你明确问到时由模型自己判断要不要建议你去查）。
- **上下文长度**：只送最近 8 轮；单条超过 2400 字会**截头留尾**（结论通常在开头）。
- **没配大模型时**：不会发出无效请求，面板里直接说明该去哪配、或者改用「生成提示词」把这段带出去问别的 AI。
- **每轮都会写一条记忆**（来源标注「对话面板」），可以在「个人画像」里看到，也能删。

> **两个验证工具的分工**：设置页的「测试连接」只问一句「回复两个字：可用」，证明不了多轮上下文和画像段真的发出去了；「试对话」会连问两轮（第一轮问水果颜色，第二轮问「我刚才问的是什么水果」），能证明上下文串起来了。

**对话是本地存档的**：会话可以导出为 Markdown（`dialogs/` 目录下按标题存），不上传任何服务器 —— 除了你配的那一个模型接口。

### 5.5 退路

不接大模型时：
- 检索式用 `arxiv_latest.build_query()` 本地词表生成（`CN2EN` 220 条 + `_PHRASE` 90 条短语）；
- 挑刺用 7 个科研方法论的结构化检查；
- 审稿意见用「生成审查提示词」导出模板，复制到任意 AI。
