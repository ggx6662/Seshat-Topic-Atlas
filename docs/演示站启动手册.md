# 演示站启动手册

这份手册只讲一件事：**怎么把「塞莎特——题谱」的演示站跑起来，改动之后怎么发到线上。**

演示站指的是 `competition/site/` 这一套纯静态页面——开场页、选题工坊、素材库、导师与院校、文献库、期刊会议、科研方法论、研究计划、关于与数据范围，一共 9 条路由。它不依赖 Python 服务，任意静态服务器都能托管。

> 如果你要找的是桌面端（Tkinter 那一套 14 页）或者本地网页体验端（`web_server.py`，5 个视图），看文末的「三个形态别弄混」。

## 二、本地跑起来

演示站是纯静态文件，用 Python 自带的 `http.server` 就行，不用装任何东西。

### 方式 A：跑「发布后的样子」（推荐）

```powershell
cd G:\Qoder\workers\knowledge-monitor\competition\site\dist
python -m http.server 4173 --bind 127.0.0.1
```

浏览器打开 **http://127.0.0.1:4173/**

之所以先跑 `dist`，是因为它就是线上那份内容；跑源目录看不出发布后的问题。

### 方式 B：边改边看（跑源目录）

```powershell
cd G:\Qoder\workers\knowledge-monitor\competition\site
python -m http.server 4174 --bind 127.0.0.1
```

浏览器打开 **http://127.0.0.1:4174/**

### 方式 C：直接双击 `index.html`

能打开，但**一定会出问题**：浏览器把 `file://` 下的 `fetch()` 判成跨域，`data/index.json` 全部加载失败，页面会一直停在「正在读取本地索引…」。所以别用这个方式判断「是不是坏了」。

## 三、端口被占用怎么办

换一个数字就行，服务端不用改任何东西：

```powershell
python -m http.server 4175 --bind 127.0.0.1
```

查是谁占着端口：

```powershell
Get-NetTCPConnection -LocalPort 4173 -State Listen | Select-Object OwningProcess
Get-Process -Id <上面的 OwningProcess>
```

关掉它：

```powershell
Stop-Process -Id <PID>
```

> `4173` 是 `check_site.mjs` 的默认地址，所以本地验证尽量留给它，别长期占着。

## 四、改完东西之后：同步到 dist

因为没有构建步骤，同步就是**把源覆盖到 dist**，唯一要小心的是**不要覆盖平台的标记文件**。

```powershell
$src = "G:\Qoder\workers\knowledge-monitor\competition\site"
$dst = "G:\Qoder\workers\knowledge-monitor\competition\site\dist"

# index.html + assets + data，三个都同步
Copy-Item "$src\index.html" $dst -Force
Copy-Item "$src\assets\*" "$dst\assets\" -Recurse -Force
Copy-Item "$src\data\*"   "$dst\data\"   -Recurse -Force
```

复制完核对一下有没有漏：

```powershell
& D:\miniconda3\python.exe -X utf8 -c @"
import hashlib, os
S, D = r'competition/site', r'competition/site/dist'
diff = []
for root, dirs, files in os.walk(S):
    if 'dist' in root.split(os.sep): continue
    for f in files:
        src = os.path.join(root, f)
        rel = os.path.relpath(src, S)
        dst = os.path.join(D, rel)
        if not os.path.exists(dst): diff.append(('dist 缺', rel))
        elif hashlib.md5(open(src,'rb').read()).hexdigest() != hashlib.md5(open(dst,'rb').read()).hexdigest():
            diff.append(('内容不同', rel))
print('差异 %d 处' % len(diff))
for t, r in diff: print('  %-6s %s' % (t, r))
"@
```

正常情况下只会剩两条，都是**本来就该有差异**的，看到它们是对的：

```
dist 缺  .选题智库.qoder.site              ← 平台标记，不属于要发布的页面
dist 缺  data\papers.json.pre-titleclean   ← 本地备份文件，不该进 dist
```

除了这两条，还有别的差异就说明没同步干净。

## 五、发布前跑一次自动验收

```powershell
# 1) 先把 dist 服务起来（另开一个窗口，别关）
cd G:\Qoder\workers\knowledge-monitor\competition\site\dist
python -m http.server 4173 --bind 127.0.0.1

# 2) 跑验收
cd G:\Qoder\workers\knowledge-monitor
node competition\scripts\check_site.mjs
```

期望输出：

```
PASS 158 / FAIL 0
NO_CONSOLE_ERRORS
ALL_CHECKS_PASSED
```

**FAIL 不为 0 就不要发布。** 脚本会打印每一条失败的断言和对应的路由。

几个可能踩到的坑：

- 脚本用 `http://127.0.0.1:4173/`，端口换了要显式给：`$env:SITE_URL="http://127.0.0.1:4175/"` 再跑。
- 脚本会启动无头 Chrome 的调试端口 `9334`。上一次没退干净时会占着，先 `Get-Process chrome | Stop-Process -Force`。
- Chrome 不在默认位置时用 `$env:CHROME_PATH="D:\...\chrome.exe"`。

## 六、发布到线上

线上地址：**https://topic-compass-jzkhsw942zj.qoder.website**

**这一步只能在 Qoder 平台操作，仓库里没有任何 CLI 或脚本能推送。**

`competition/site/.选题智库.qoder.site` 里虽然有 `projectId` / `siteId` / `deploymentId` / `releaseId`，但那是**上一次发布的回执记录**，不是可调用的接口——**不要照抄这些 ID 去构造发布请求**。真正的上传走平台自己的通道。

那一轮发布的完整证据链（三处改动、核对表、截图踩坑）记在 [`docs/origin/题谱-发布与交接手册-2026-11-20.md`](origin/题谱-发布与交接手册-2026-11-20.md)，需要追溯时看它。

操作顺序：

1. 确认 `competition/site/dist/` 已经是最新的（回到第四节核对一遍）
2. 确认 `check_site.mjs` 全过（第五节）
3. 打开 Qoder，进入这个项目，找到「发布 / 部署」入口
4. 指向 `competition/site/dist/` 重新发布
5. 等平台返回新的 `releaseId`

### 发布后核对

```powershell
# 首页是否 200
(Invoke-WebRequest "https://topic-compass-jzkhsw942zj.qoder.website" -Method Head).StatusCode

# 关键特征：新版 index.html 里有 id="ihArt"，旧版没有
$h = (Invoke-WebRequest "https://topic-compass-jzkhsw942zj.qoder.website" -UseBasicParsing).Content
if ($h -match 'id="ihArt"') { "新版本已上线" } else { "还是旧版，回去重新发布" }

# 样式里是否有开场页窄高窗口的修复断点
$c = (Invoke-WebRequest "https://topic-compass-jzkhsw942zj.qoder.website/assets/intro.css" -UseBasicParsing).Content
if ($c -match 'min-width: 1121px') { "开场页修复已上线" } else { "intro.css 还是旧版" }
```

`id="ihArt"` 和 `min-width: 1121px` 是 2026-11-20 那次开场页修复留下的特征串，拿它们对比新旧版最省事。

## 七、常见故障对照

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面一直停在「正在读取本地索引…」 | 用 `file://` 打开了，或者服务起在了错误的目录 | 用 `python -m http.server`，并且 `cd` 到 `dist/` |
| 控制台一片 404，全是 `/data/xxx.json` | 服务起在了仓库根目录 | `cd competition\site\dist` 再起服务 |
| 截图 / 页面看起来「一片空白」，只剩背景 | 开场页入场动画从 `opacity:0` 起步，无头浏览器不推进动画 | 截图时加 `--force-prefers-reduced-motion`；真人浏览器不受影响 |
| 开场页右半边空着，只有一个椭圆环 | 窗口「窄而高」（比如 1189×1475）触发了旧的断点 | 2026-11-20 已修复，确认发布的是新版（见第六节核对） |
| 图上没有塞莎特插画，右栏干净收起 | `seshat-atlas.webp` 加载失败，代码主动隐藏了 | 检查 `assets/` 下这个文件在不在、有没有被压坏 |
| 发布后线上还是老内容 | 平台缓存的旧 `releaseId`，或者发布目录指错了 | 重新发布一次，用第六节的 `id="ihArt"` 核对 |

## 八、三个形态别弄混

仓库里有三套界面，**数据口径不一样**，排查问题前先分清是哪一个：

| 形态 | 怎么启动 | 页面数 | 口径 |
|---|---|---|---|
| 桌面端 | `python app_main.py` | 14 页 | 方向 536、学者 21,847、本地 PDF 345 |
| 网页体验端 | `python web_server.py`（默认 http://127.0.0.1:8765） | 5 个视图 | 接口 7 个开放、5 个拒绝 |
| **演示站（本手册）** | `python -m http.server` 指向 `competition/site/dist` | 9 条路由 | 方向 531、学者 18,296、本地文献 345 |

网页体验端端口被占用时会自动往后找一个空端口，不会直接报错，所以看到 8766 也别意外。
