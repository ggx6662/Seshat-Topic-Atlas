## 1. 一句话说明

给一个模糊的研究方向，系统先识别方向与应用场景，再按关键词关联强度拆成 **12–22 条候选选题**，逐条给出为什么值得做、可证伪问题和两周最小验证；再用 **9 项结构清单**检查它能不能被核查，最后接到导师、期刊、数据素材与研究计划。

不是给选题打一个 0–100 分，而是把「这条题到底缺什么」摆出来。

## 4. 为什么做

现有的选题工具常落在两个极端：

1. **只给一个分数**。把「消融、baseline、指标、单卡 GPU」这些词堆在一起，也可能拿到高分；高分会让用户误以为题目已经成熟。
2. **什么都不说**。只返回一堆论文，用户仍然不知道下一步该做什么。

这个作品选择第三条路：**不打质量分，只做结构核查**。

结构体检逐项检查：

> 问题具体 / 机制可检验 / baseline 点名 / 数据与划分 / 指标定义 / 消融设计 / 资源估算 / 止损条件 / 范围收敛

「指标」两个字不算定义了指标，必须出现可测的度量；「消融」两个字不算设计了消融，必须说明消融什么、与什么同条件对比。系统给出阶段（0–4）、缺失项和可直接执行的修复动作，但**不替用户决定做哪条题**。

同时明确说出边界：

- 候选的「相关 / 新颖 / 可行」分数只由方向与切入角度计算，**不代表文献新颖性，也不是评审结论**；
- 数据规模、方向—数据集—指标—基线的关系集中在「素材库」核对，候选页不再混入全库总量或测试性演示卡；
- 真正的 53.8 万篇 arXiv 近邻核查在桌面完整版中完成，Web 演示版不声称查过全网。

## 5. 怎么用（5 步以内）

1. 打开 https://topic-compass-jzkhsw942zj.qoder.website ，先看到开场页，点「进入系统」或按回车直接进入选题工坊；在这里输入方向（输入 2 个字即出现联想，可用 `↑` / `↓` 选择、`Enter` 确认、`Escape` 关闭），点「识别方向」或选一个联想项；也可切换「标签组合 / 全部方向」。三种入口任选：直接输入「红外小目标检测」；切到「标签组合」勾选应用场景与任务偏好，从推荐列表里选方向；或切到「全部方向」先选大类、再按关联强度选小方向。
2. 在方向确认页核对识别结果与应用场景，点「确认方向，生成候选」；在左侧 12–22 条候选里点一条，读「为什么值得做」「可证伪问题」「两周最小验证」，以及该方向最常用的公开数据集、指标与基线方法。
3. 切到「结构体检」，点「载入示例（红外场景）」再点「体检这版描述」，看 9 项通过情况、阶段和缺失项修复建议。
4. 点「存入研究计划」，在 `#/plan` 设置截止日期与每周投入，查看概览、倒推阶段、里程碑状态和待办。
5. 到「科研方法论」勾选已完成的科研准备、选择研究阶段并填写约束（如算力与数据审批），查看按所选方向生成的完整提示词；再点「复制提示词」。之后到「导师与院校」用平铺 / 列表切换浏览全部学者，按地区筛选（地区按院校所在地归档），点开任一学者查看院校所在地区、院校官网、已核验个人主页与 ORCID / DBLP 入口；切到「院校」页签可按校名搜索或按地区筛选学校，点进「中国科学技术大学」查看该校全部导师，再返回院校列表；需要核对数据规模与关系时进「素材库」。移动端先用 390px 宽打开，确认详情会排到候选列表上方；再用手机浏览器打开同一链接，确认底部导航为 5 项横排、页面无横向溢出。结果页点「调整方向」可回到确认页并保留刚才的方向与应用选择。可以再输入「12」验证：页面会清空旧结果并提示输入不像研究方向，不会给出联想或候选。

## 6. 怎么用 Qoder 做出来的

### 6.1 起点与边界

桌面原型在进入 Qoder 之前已经存在（Python / Tkinter，本地运行）。本次**没有把已有桌面代码说成从零生成**，而是在 Qoder 副本中完成了参赛所需的 Web 化增量：

- 保留原项目不动，把源码与必要数据复制到 `G:\Qoder\workers\knowledge-monitor`；
- 在 Qoder 中阅读桌面版的产品定义、设计约定、数据结构与核心算法；
- 把「可离线、可公网打开、无需密钥」作为 Web 演示版的硬约束。

### 6.2 实际完成的工作

1. **数据导出层**：编写 `competition/scripts/export_web_data.py` 与 `export_scholars.mjs`，只读调用原桌面引擎与公开元数据（方向库、候选生成、学者索引、venue、方法论、CSRankings / ORCID），导出按方向拆分的静态 JSON；不写入用户数据。
2. **Web 前端**：实现 `competition/site/` 下的静态 SPA，包括 hash 路由、开场页与 8 个页面、输入校验与方向识别、按关联强度生成 12–22 条候选、9 项体检的 JS 版本、示例方向兜底、学者 / 论文 / venue / 素材库展示，以及 `localStorage` 研究计划。
3. **真实数据**：导出 531 个方向文件与 `index.json`、`advisors.json`、`venues.json`、`materials.json`；整理 552 个公开基准数据集（全部附官方主页，401 个附来源论文；按方向给出常用数据集、指标与基线方法）与 37 个应用领域标签；学者按 ORCID 去重后全部进入 Web 目录；所有页面数字来自真实导出，不手填。
4. **响应式与可访问性**：补齐桌面 / 平板 / 手机布局、深浅主题、移动端详情前置、筛选条横滑、键盘焦点与 reduced-motion。
5. **浏览器验收**：用无头 Chrome 对 7 个路由 × 3 种宽度做自动化回归，检查标题、控制台错误、横向溢出、无效输入提示与旧结果清理、5 个示例的候选 / 学者 / venue 数量、直达路由默认状态、结果页回到方向确认、移动端详情顺序、标签组合、两级目录关联强度、素材库关系、地区筛选、导师平铺 / 列表与详情弹层；另生成桌面 / 平板 / 手机截图。
6. **界面重构**：完成可用版本后，重新研究科研工具的界面层级，重写整套 CSS 为“科研档案柜 / 学术期刊工作台”视觉系统，并修正桌面误显示移动控件、移动端 Toast 遮挡、详情页签裁切、路由切换保留滚动位置等问题。
