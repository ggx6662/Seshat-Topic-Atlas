# 【StudyHack】题谱：把研究方向拆成可核查选题

## 自我介绍

我是【姓名 / 昵称】，【学校 / 专业 / 年级】的学生。我做过【一句话相关经历，例如：本地文献管理 / 科研训练 / 课程项目】。平时的困扰很具体：知道一个大方向，却不知道哪一个问题能在几周内验证、哪条题值得继续做。这个作品来自我自己的选题过程。

## 作品是什么

「题谱」是一个**无需登录、无需 API Key、打开即用**的科研选题 Web 工作台。名字取“问题的谱系”之意：把一个大方向展开成一组彼此可比较、可核查的问题。

界面按“研究图谱 / 学术工作台”来设计：奶油纸面、墨蓝标题、赭棕主笔、金色批注，大圆角卡片配柔和阴影。打开根地址先进入全屏开场页：左侧「知识是人类缔造巴别塔的阶梯，思想是构建未来的桥梁」三行浮起，右侧是工作台界面预览（方向输入、候选问题与匹配度、数据集 / 导师 / 期刊卡片），下方给出 501 个方向、502 个数据集、18,296 位学者与 701 个 venue 的快照；点「进入系统」或按回车直接进入选题工坊。工坊方向输入框带实时方向 / 别名 / 关键词联想，输入后原地进入识别流程。桌面、平板、手机和深浅主题共用同一套信息层级。

给它一个研究方向，它**不会直接甩出候选**：先做输入校验，再进入方向识别页，告诉你它把这个说法理解成了哪个方向、属于哪个大类、命中了哪些词、置信度是多少，以及识别到的应用场景；如果方向库里没有这个说法，会直接说明并给出全库兜底选项。输入太短、只有数字或符号时不会硬猜，也不会留下上一次的结果。不想自己描述时，也可以从 **37 个应用领域标签 × 5 个任务偏好**里组合，或按 24 个学科大类（另设应用领域聚合）、再按知识库关键词的强 / 中 / 弱关联挑选小方向。你确认方向之后，它才按关联强度生成 **12–22 条候选选题**，每条都写清楚：为什么值得做、可证伪的问题是什么、两周内能做的最小验证是什么，并列出该方向论文里常用的公开数据集、评测指标与基线方法。选中一条后，再用 **9 项结构清单**检查它能不能被别人核查——问题是否具体、机制是否可检验、baseline 是否点名、数据和划分是否说清、指标是否可测、消融是否设计、算力是否估算、有没有止损条件、范围是否收敛。相关 / 新颖 / 可行三条进度条会标出当次候选内的中位数、差值和排名，差异能直接读出来；结果页点「调整方向」会回到确认页并保留刚才的方向与应用选择。

它不会给选题打一个 0–100 的质量分。因为词堆也能骗到高分。它只把「还缺什么、下一步怎么补」摆出来。

除了选题工坊，作品里还有：

- **素材库**：单独核对数据规模与关系——501 个方向、502 个公开数据集、345 篇文献统计、701 个 venue 与学者覆盖；502 个数据集全部附官方主页，354 个另附来源或代表论文，按大类筛选后可查看方向—数据集—指标—基线—代表论文的关系；
- **导师与院校**：按方向匹配学者，或浏览全部 18,296 位去重学者；平铺 / 列表双视图与分页加载，地区筛选覆盖 9 个大区 / 46 个地区；地区按院校所在机构库（OpenAlex 机构地理字段 + ROR）归档，18,296 位学者中 16,753 位已归档，1,543 位因机构地理字段缺失明确标为「地区待核验」，不强行归入海外；新增「院校」页签，把 18,296 位学者聚合成 **2,547 所学校**，可按校名搜索、按地区筛选，点进任一学校就能看到该校全部导师；点开学者可查看所在地区、真实个人主页、院校官网、ORCID、ROR、DBLP 与 Google Scholar 入口；9,774 个 ORCID 标识（9,730 个有公开快照）做过公开记录离线快照，8,602 位姓名匹配，5,322 位有公开作品；665 位方向学者按当前任职与 ROR 核验机构（例如 Andrew Zisserman 由上海交通大学改为 University of Oxford），并展示 2021–2026 发表活跃度与近期论文；仅含海外任职、姓名不一致或弱匹配的同名记录不自动合并，未覆盖快照的学者也会明确标注原因；没有核验主页时不跳转搜索引擎；
- **论文库**：8,412 篇 ORCID 公开学术作品，来自 883 位方向推荐学者、覆盖 25 个领域，全部带领域分类；按题目、学者、年份、类型、领域筛选并分页加载，点标题跳 DOI，也可从学者详情直接进入该学者的论文列表；
- **期刊会议**：701 个 venue，「按方向推荐」页签内可直接输入方向搜索，全部目录支持搜索、CCF 等级、类型与领域筛选；两种视图都可切换平铺 / 列表；整张卡片可点开详情，查看定位说明、CCF 2026 等级含义、推荐逻辑、官网与「在论文库搜索」入口；
- **科研方法论**：7 套结构化方法，可展开步骤并复制提示词；
- **研究计划**：存入选题，设置截止日期和每周投入，生成倒推阶段与待办。

公网体验地址：**https://topic-compass-jzkhsw942zj.qoder.website**

所有数据由桌面版引擎离线导出，页面不调用在线模型，也不包含任何密钥。研究计划只保存在访问者自己的浏览器里。

## 为什么做

我开始做这个工具，是因为「从方向到题目」中间那一段没人教。

导师给的题目常常要么太宽——「你自己找找」；要么太窄——「接着师兄的做」。网上能搜到论文，但搜到论文不等于知道下一步做什么。很多工具会直接给一个「创新性 87 分」，可这个分数既不能解释，也不能验证；把「消融、baseline、指标、单卡 GPU」这些词堆在一起，它也可能给高分。高分反而让人误以为题目已经成熟。

所以我换了一个判断方式：**不打分，只核查结构**。一条题如果说不清问题、机制、对照、数据和失败判据，它就不该被叫作「可执行」。系统负责把缺失项和修复动作列出来，做不做、做哪条，仍然由使用者决定。

我也尽量不隐藏边界。候选的「新颖性」只是方向与角度的结构估计，不是文献查新结论；学者个人主页只采用 CSRankings 与 ORCID 的公开链接，未收录时明确改由院校官网与 ORCID 核验；地区按院校所在机构库（OpenAlex 机构地理字段 + ROR）归档，但仍有 1,543 位因机构地理字段缺失标为「地区待核验」；9,730 个 ORCID 快照中 8,602 位姓名匹配、5,322 位有公开作品，625 个仅含海外任职、484 个姓名不一致与 19 个弱匹配记录不自动合并，其余学者会直接标注原因，不会假装所有人都已核验；ORCID 与 ROR 是 2026-11-18 的离线快照，打开页面时不调用外部接口；论文库只覆盖 883 位方向推荐学者的公开作品，不是全部学者或全站检索；方向识别只做 501 个方向名 / 术语 / 关键词与应用场景映射的字符串匹配，不是语义检索；推荐数据集来自公开基准的整理，是否适合具体题目仍需读原论文确认。真正的 53.8 万篇 arXiv 近邻核查在桌面完整版里完成。把边界写在结论旁边，比藏在「关于」页里更重要。

## 怎么用（5 步以内）

1. 打开 **https://topic-compass-jzkhsw942zj.qoder.website**，点「进入系统」进入工作台，再点示例「红外小目标检测」，先看识别页给出的方向、大类、匹配依据与应用场景，再点「确认方向，生成候选」；也可以先试「标签组合」勾选应用场景与任务，或先选大类、再按关联强度挑小方向。
2. 在左侧 12–22 条候选里点一条，读「为什么值得做」「可证伪问题」「两周最小验证」，以及推荐数据集、指标与基线；再看三维度条的中位数、差值与排名。
3. 切到「结构体检」，点「载入示例（红外场景）」再点「体检这版描述」，看 9 项通过情况、当前阶段和缺失项修复建议。
4. 点「存入研究计划」，到「研究计划」页设置截止日期与每周投入，查看倒推阶段和待办。
5. 打开「素材库」，按大类筛选并点开一个方向，查看数据集、指标、基线与代表论文；到「导师与院校」切换平铺 / 列表，按地区筛选并搜索一位学者（例如 Zisserman），核对 ORCID 修正后的机构、ROR 链接、发表活跃度与近期论文，再点「在论文库查看这位学者」；切到「院校」页签，搜索「中国科学技术大学」并点进去，查看该校全部导师，再返回院校列表；到「期刊会议」在「按方向推荐」里输入「红外小目标检测」直接搜索，再切到「全部 701 个」把视图切到列表；也可以回到工坊输入「12」点识别，确认页面会清空旧结果并提示输入不像研究方向，而不是硬给联想。

一次完整体验大约 1–3 分钟；手机浏览器也可以直接打开。

## 怎么用 Qoder 做出来的

先说清楚起点：桌面原型是此前已有的本地 Python / Tkinter 项目，不是这次从零生成。我把它完整复制到 Qoder 工作区，原项目保持不动，然后在 Qoder 中完成了参赛所需的 Web 化增量。

具体过程：

1. **读代码与产品约束**：在 Qoder 中阅读桌面版的产品定义、设计约定、方向库、候选生成、结构体检、学者与 venue 数据结构，确定 Web 版只移植确定性算法，不接在线模型。
2. **做数据导出**：编写 Python 导出脚本与一个幂等的应用扩库脚本，把 24 个学科大类、501 个方向、345 篇本地文献统计、701 个 venue 导出为静态 JSON；合并 21,798 条学者记录、按 ORCID 去重后得到 18,296 位学者，并从 CSRankings、ORCID 与 OpenAlex 机构记录补齐真实主页与院校官网；另整理 37 个应用领域标签与 502 个公开基准数据集；再用可断点续跑的 ORCID / ROR 快照覆盖 9,774 个 ORCID 标识（9,730 个有公开快照），8,602 位姓名匹配、5,322 位有公开作品，导出 8,412 篇论文；不写入用户数据。
3. **实现 Web 版**：在 Qoder 中完成静态 SPA 的开场页与 8 个页面、hash 路由、输入校验、「先识别方向、确认后生成候选」的两步流程、搜索 / 标签组合 / 两级目录三种入口、按关联强度生成 12–22 条候选、推荐数据集、9 项结构体检、示例兜底、素材库、导师平铺 / 列表与详情弹层、论文库筛选与分页、期刊展示，以及基于 `localStorage` 的研究计划。
4. **验收与修正**：用无头浏览器对 8 个路由 × 桌面 / 平板 / 手机三种宽度做自动化回归，检查控制台错误、横向溢出、识别页与未命中兜底、无效输入提示与旧结果清理、结果页回到方向确认、标签组合、两级目录关联强度、素材库、数据集、三维度差异、地区目录、院校地区全覆盖与按地区筛选、院校目录与点进学校查看导师、导师平铺 / 列表与详情链接、ORCID 机构修正、发表活跃度、期刊页方向搜索与平铺 / 列表、论文库筛选与分页；期间修掉了直达页面默认状态、示例方向模式、手机端详情顺序、筛选条布局、短数字输入误出联想、旧结果残留、手机端标签重复、院校行被长校名撑宽等问题。
5. **做减法**：按反馈移除了此前的题谱星图页面，删掉对应路由、导航、脚本、样式、数据字段和截图，保留经得起演示的开场页与 8 个页面。
6. **发布**：通过 Qoder Sites 发布静态产物，验证公网可访问，并把访问策略设为 public，让评委点开链接就能体验，不需要账号或安装。
